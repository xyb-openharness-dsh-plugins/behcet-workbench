# 白塞病患者与授权代记者：用户研究草案

> **访谈 0 次，临床审核 0 次；尚无患者验证或原型确认。**本文中的患者需求、情绪、应对方式和场景句均为设计假设，不是患者或代记者引语，也不代表普遍经验。医学表述尚待临床审核。

## 范围和方法

目标对象是成年白塞病患者及其授权代记者，覆盖疑似、确诊到长期随访。项目既定目标是帮助用户整理发作、检查、治疗及多科就诊资料，核对来源并准备复诊；见 [需求起点](BRIEF.md) 和 [规格草案](SPEC.md)。这些项目要求不是患者访谈发现。工作台不作诊断、病情分级、治疗选择或因果判断。

本次是有限的桌面研究及设计推导，没有访谈、问卷、患者观察、可用性测试或临床审核。专业综述可帮助识别医学背景，不能证明患者想要某项功能。以下没有已验证效果，也没有可依据的患者需求排名。

## 主要需求假设与待验证链

下表的困难、应对、情绪和期望均为假设；E01 只支持医学背景，E05 只支持项目范围。顺序不是需求排名。

| 编号与触发 | 假设的困难及现有应对 | 可能的负担、期望和缺口 | 待验证的需求与问题 | 场景 |
|---|---|---|---|---|
| N01 疑似阶段反复口腔或其他部位溃疡 | 可能依赖记忆或照片回忆每次时间 | 可能难以向医生说明变化；希望整理发作过程 | 是否愿在不适时记录？最少需要哪些字段？ | S01 |
| N02 多科就诊、资料分散 | 可能在纸单、手机和不同机构记录间查找 | 可能重复叙述；希望按时间回源 | 时间线是否比原件目录更有帮助？跨院优先级多高？ | S02 |
| N03 新出现眼部或神经相关症状 | 可能不清楚如何求助 | 可能担心延误；希望获得可信求助信息 | 哪些文字能被正确理解？内容和紧急边界须临床审核 | S03 |

| N08 复查时对比检验 | 可能混淆不同日期、单位或方法 | 希望回看报告原件与变化 | 哪些项目有意义？何时可比须由专业人员核定 | S10 |
| N09 本人低精力、授权他人代记 | 双方可能对谁能记录、看见什么有不同期待 | 希望减少负担并保有自主权 | 授权、撤回及历史记录处理应如何设计？ | S11 |

| N12 治疗前的检查安排 | 可能只记得「抽过血」，记不清查了什么、什么时候 | 希望把医生安排过的检查原样带去看诊 | 抄录式记录是否足够？如何避免暗示「缺项」？ | S15 |

疲劳、认知与体力、数字能力、地域与费用、家庭分工、身体形象、性健康、生育及治疗期间失控感均是后续访谈主题，不能预设每位患者均有这些体验。E01 支持疾病可复发及多系统受累，不支持任何特定心理体验或社会负担的发生率。

## 待讨论的取舍

- **记录完整性与隐私**：希望向医生说明所有相关情况，与不愿让代记者或外部服务看到敏感内容可能冲突。现有产品约束是导出、AI 和摘要默认排除私密内容；如何由患者显式加入某次分享、代记者权限如何限制，尚待确认。
- **信息详尽与低精力**：详细字段可能提高回顾价值，也可能增加发作时负担；先验证最少输入和稍后补充。
- **求助信息与医学边界**：需要可理解的求助信息，但不能让系统判断具体疾病或治疗。具体提示和使用条件须先临床审核。
- **代记便利与自主权**：代记可能减轻负担，授权撤回后历史资料的保留与访问规则尚未决定。

| 缺口 | 下一步 | 验收证据 |
|---|---|---|
| 患者和授权代记者真实需求 | 招募不同阶段、受累情况及数字能力的成年参与者，访谈并检验关键任务；样本及伦理流程由研究方案确定 | 记录招募、方法、样本局限、匿名发现及与假设冲突之处 |
| 医学安全与适用性 | 核对已取得的中国 2025 指南原件（E08），补取其他适用原文，并邀请相关临床专业人员审核求助信息、字段和解释 | 逐条记录来源版本、审核者、日期、修改及未解决项 |
| 原型与可用性 | 需求讨论后制定交互路径并进行原型测试 | 分别记录用户验证、临床审核、原型确认及失败恢复结果 |
| 本地资源与技术 | 独立核实机构、服务边界及断网/导出能力 | 标明核查日期和限制；实际测试前均标未验证 |
