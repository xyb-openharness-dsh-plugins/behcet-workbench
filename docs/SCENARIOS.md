# 白塞病患者场景候选

> **文档编号**：SCENARIOS ｜ **版本**：`v0.1.0-draft.1`（2026-11-02）
> **状态：草案；患者及代记者访谈 0 次，临床审核 0 次，用户验证 0 次，原型确认 0 次。**本文件所有场景句都是设计假设，不是患者或代记者引语；优先级仅供讨论，尚未签认。医学内容及适用性均待临床审核。

服务成年白塞病患者及授权代记者，覆盖疑似、确诊和长期随访。按 [需求起点](BRIEF.md) 与 [规格草案](SPEC.md)，工作台整理资料、回源和准备沟通，不诊断、不分级、不决定治疗或判断因果。未知、未检测、待结果、检测失败及阴性须区分；未检测不等于阴性。

证据及局限见 [用户研究](USER-RESEARCH.md)；就诊、自查、复查路径见 [患者流程](PATIENT-FLOW.md)。器官受累的医学背景见该研究 E01 综述，不能证明患者需求。每条患者任务、收益及排序均待研究验证。

## 初步取舍与证据缺口

建议先讨论 S01、S02、S09、S11、S12 的记录—核对—回源—复诊闭环；S03 的求助内容需要临床审核后方可使用；S04–S08、S10、S13 依患者访谈及医学审核调整；S14 因本地资源未核实暂缓；S15 依赖临床核验「哪些检查属于治疗前安排」的表述口径，**在核验通过前只做纯事实抄录**，不做缺项判断。该顺序是设计建议，并非患者需求排序或一期承诺。授权如何证明与撤回、私密资料显式加入各出口的规则、断网范围、低精力输入负担及跨院资料优先级均待患者和代记者验证。

针对白塞病的高价值审核尚未完成：受累表现可跨多个器官，但具体场景的病种特异性、频次、价值及医学口径均无患者验证；不将通用的用药记录或导出当作病种特异覆盖。当前仅有场景和验收候选；[数据结构](SCHEMA.md)尚未完成。界面层已出候选（[页面树](UI-DESIGN.md) §1：8 一级 / 28 二级）但未签认，且**孤儿二级页 12 个**（见该文件 §2.1），尚未与本文双向穷举。**验收编号说明**：[验收记录](ACCEPTANCE.md) 的 `ACC-nn` 是交付/装机验收，与本文的 `AC01–AC15` 场景验收不是同一套编号，对应关系与待办见该文件开头。**场景→页面→验收的四套分类法对照表见 [UI-DESIGN.md §2](UI-DESIGN.md)**（唯一对照表）。**G1 未签**；需后续独立审核逐场景评分、补模块、字段、交互与验收，不能因本文有候选即视为通过。

## 候选验收（均未执行）

每条操作及预期是将来的验证条件，不是现有功能或已通过测试。涉及保存、导出、网络和授权须在实际实现后分别测试。

- **AC01**：新增开始日期已知、结束日期未知的口腔发作；回看显示未知，未将其当作结束或零天。
- **AC02**：录入来自两科的同日记录，打开时间线并回源；两条均可见且分别指向原件。资料冲突时保留两条。
- **AC03**：无已审核内容时打开求助信息，明确显示内容待审核，不展示自行诊断结果；断网时呈现实际可用状态。
- **AC04**：记录血管检查日期及原文后回源；缺少原件时标记缺失，不伪造报告。
- **AC05**：录入腹部症状和肠道检查后回顾；时间与来源分别显示，界面不宣称因果。
- **AC06**：记录治疗原文后更正；能看到更正及原来源，不出现自行调整提示。
- **AC07**：登记医生给出的复查原文和来源；未填写日期时显示未知，不自动生成医学间隔。
- **AC08**：记录疲劳对工作的影响后回看；原文保留，不生成病情分级。
- **AC09**：将一条记录标为私密，分别预览导出、摘要及 AI 输入；默认均不含该条。显式纳入规则须先确认并另行验证。
- **AC10**：录入不同单位或方法的两次检验；分别显示来源与单位，不作为可比序列连线；单条不连线。
- **AC11**：授权代记者记录后回看，显示记录主体及来源；未授权状态不得写入，撤权后的处理待确认。
- **AC12**：选择两份资料和一个问题并预览，输出集合与选择一致；导出失败后保留选择并允许重试。
- **AC13**：保存私密问题，默认预览中不包含；不生成生育或用药建议。
- **AC14**：若未来提供资源条目，显示来源、核对日期及地区和服务局限；未核实条目明确标注，不作为转介推荐。
- **AC15**：抄录医生安排的用药前检查后回看；只显示用户抄录的名目、日期与来源。断言：界面**不出现**「缺某项」「还差几项」「可以开始用药」类结论；未填日期显示未知，不自动推算。
