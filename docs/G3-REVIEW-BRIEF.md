# G3 数据合同评审摘要

依据：`docs/DATA-MODEL-DRAFT.md` v0.1.0-draft.13，以该合同为准。本摘要整理评审范围，不代替签认或实现验证。G2 已由用户确认；G3 尚未确认。原型使用合成数据，0 患者访谈、0 临床审核。

## 拟确认的边界

- 数据按患者主体隔离；授权代记者的访问需真实身份与权限能力，当前原型不具备该能力。
- 私密及隐私未知内容本版不得进入 AI；导出与历史访问按合同逐条控制。来源不可核实的旧数据默认受保护。
- 原件登记与候选抽取分开；候选须经确认才成为事实。模拟解析不证明真实云解析可用。
- 日期不确定时保留原文，不凭导入时间或格式猜测。来源、版本与修订历史保留可追溯信息，不能猜测原件指针或作者。
- 旧数据中“原件已移除”可能来自解除关联或删除，不能凭文字推断哪一种；迁移规则是草案，尚未实现。

## 跨主体约束探索（2026-11-04）

使用 Node v24.22.2、SQLite 3.53.4 的内存库，针对 `record_revision` 与 `source_document` 及最小桩表做负向实验：现有示例的单列外键允许跨主体引用，并允许修改关联父行的主体；`foreign_key_check` 对这些跨主体但引用存在的行返回零错误。候选复合外键方案在启用外键的条件下，所测 9 个合法及非法引用用例符合预期；外键关闭时仍需事务内检查，主体列必须非空。另一候选方案使用子表触发器和父表主体不可变触发器，仍需覆盖全部写路径。两种方案均未选定或用于生产。

该实验仅覆盖一类引用和合成桩表；不能证明其余引用、真实迁移、授权、并发或崩溃恢复安全。表重建、外键逐连接启用以及迁移后的不变量检查仍是待验证事项；Q-30 继续阻塞 G3。可在仓库根目录运行 `node scripts/probe-rev-source-subject.mjs` 复现；当前已知缺口复现时退出码为 1，探针不是验收，也未接入常规检查。探针自身测试可用 `node --test test/probes/probe-rev-source-subject.test.mjs` 单独运行。

## 恢复风险探索（2026-11-04）

合成 SQLite 实验使用 `VACUUM INTO` 快照，再复制为同一临时目录中的新数据库文件；60 项断言符合脚本预期，并未实现完整目录恢复流程。所测模型中，清空仍有对应效果的回执再重试创建可产生重复效果；局部重建导致事实与回执不一致后的重试风险是机制推断，脚本没有完整执行该重试。效果行的幂等标识仅在效果行仍存在的模型中可用于识别，不证明跨回滚恰好执行一次。

特别是备份 T0 后，T1 命令成功且客户端已收到响应或外部服务已收到请求，再恢复 T0 时，效果行与回执可同时消失：不重试可能丢失已确认的本地效果，重试可能重复外部副作用。库内标识无法单独消除这一风险；外部幂等、独立日志、对账或人工处理均需另行设计和验证。合成反例可运行 `node --test test/probes/restore-rollback.test.mjs`：以临时文件模拟外部副作用，不联网，不验证生产实现。

实验也演示恢复旧库可能使已撤销的授权或已收紧的隐私状态回退，并在一个硬编码目录中观察到库外孤儿导出文件；它没有验证完整产物目录对账。撤销计数的示例依赖可信、不可回滚且与同一线性历史同步的外部记录等前提，这些前提尚未验证，不能据此确认撤权安全。恢复策略需同时考虑授权与隐私重核、库外产物对账、外部副作用，以及恢复中断和客户端重试；清空回执、恢复代次和效果级幂等均为待评估方案，不将任一种标为已选定。Q-28、Q-29 继续阻塞 G3。实验脚本仅在临时目录，未作为长期工件保存；未验证真实旧库、宿主、并发和崩溃恢复。
