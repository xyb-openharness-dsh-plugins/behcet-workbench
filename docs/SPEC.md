## 用户与目标

成年患者与其授权代记者，从疑似阶段至长期随访。帮助用户记录发作、整理检查与治疗资料、回顾时间变化、准备跨科复诊。

### 明确不做（边界清单）

工作台**不作诊断、不作分型判定、不作疾病活动度评分、不作用药推荐、不作预后判断、不作生存期估计、不作因果判断、不作临床试验匹配、不采用肿瘤分期与治疗线序**。以上是本文的边界条款；`docs/DIFF-MATRIX.md` §4「明确不做」行与 `docs/INTERACTION-DESIGN.md` 原则段引用本清单，如与本文不一致以本文为准。

边界落地方式：产品只呈现**用户自己记录的事实、原文与出处**，以及**用户自己选择的状态**（例如「这次算不算一次发作」由用户标注，不由算法判定）；所有涉及医学含义的短语在临床核验通过前一律停留在**占位 + 待核**状态，不得作为可读结论上线。

## 候选功能与验收

| 功能 | 患者视角假设（非引语） | 可验证结果 |
|---|---|---|
| 发作记录 | 我想记住溃疡何时出现、怎样变化 | 记录日期、部位、用户描述及来源；可修订回看，支持私密标记 |
| 眼部与其他器官资料 | 我想向不同科室说明症状和检查的时间顺序 | 症状与报告可回源；缺项显示未知，不能生成医学判断 |
| 检验与一图秀 | 我想在复诊时看清自己记录的变化 | 同源指标目录、单位方法分组、单点不连线、治疗事件分层，图形不能暗示因果 |
| 治疗记录 | 我想记住使用过的药物和自己的感受 | 保留时间、剂量原文与来源及修订，不提示自行调整 |
| 复诊准备 | 我想带着选好的资料和问题去看医生 | 可选择、预览、回源；私密记录默认排除，导出内容与选择一致 |
| 资料整理 | 我想核对导入资料后再保存 | 云解析显式触发并告知发送原件，抽取仅为候选，用户逐项核对 |
| 用药前检查记录 | 我怕忘了医生安排过哪些检查 | 只抄录检查名原文、日期与来源（S15）；**不生成缺项清单、不判断还差哪项** |
| 原生 Agent | 我想讨论自己选择的内容而不丢失已有输入 | 中间业务区、右侧可调整面板；会话归属、草稿冲突、隐私过滤及不可用状态均须验证 |

## 数据和安全边界

用户明确选择资料目录；不推断、不静默创建。领域事实、来源、记录主体及修订与页面读模型分离。原型数据为合成数据；无患者数据。所有功能与字段尚待研究和 G1 审核，模型尚未冻结。

### 私密的三个出口（逐个定义，不靠“等”字）

「三出口默认排除」此前只写了短语，未定义对象。现逐条定义，**每条都要有可断言的落点**：

| 出口 | 定义（本产品的具体物） | 私密内容的默认行为 | 显式纳入方式 | 落点 |
| --- | --- | --- | --- | --- |
| **导出** | `复诊与准备` 线生成的**就诊材料包文件**（用户主动下载/另存） | 不进文件；导出预览里不出现 | 在导出预览里**逐条勾选**该条后才写入文件 | `INTERACTION-DESIGN.md` §三 复诊准备行、AC12 |
| **AI 上下文** | 任何发往原生 Agent 会话的 `prompt`（含 34 号一键发送与 `discussFacts`） | 不进 prompt | 当前设计禁止私密记录进入 AI；是否允许本人逐条授权是未决问题，确认并验证前禁止发送 | 34 号契约 + `INTERACTION-DESIGN.md` §四 IP11 |
| **摘要** | `复诊与准备` 线在导出**之前**的**可读摘要视图**（把选中的事实按时间串成一段人话预览），不是独立页面、不落库、不单独存储 | 不进摘要 | 与导出**共用同一选择集**：勾选一次，摘要与文件同步变化 | `UI-DESIGN.md` 页面树 `复诊与准备 / 摘要预览`；AC09 |

共同约束：私密是**数据结构属性**，三出口默认排除。摘要与导出可由本人逐条选择纳入；AI 出口当前禁止纳入，例外机制尚未确定。AI 不生成或推断私密话题。

### 云解析（原件离开本机）的留存与删除

云解析把原件送出本机，同意的对象必须写清，否则「每次授权」是空话：

1. **发送前告知**：写明服务方、将发送的原件、用途，用户显式触发才发送；不静默上传。
2. **留存**：不承诺服务方不留存；产品侧**不缓存原始文件**，只保留用户确认后的抽取候选与原文出处。
3. **删除**：用户可在资料条目上撤回该次解析，撤回后删除本地候选与缓存；**服务方侧删除能力未核实**，因此文案不得声称「已从服务器删除」。
4. **二次使用**：不将解析内容用于训练、画像或与本次记录无关的用途；不得二次外发。
5. **未核实项**：MinerU 服务本身未核实（见 §未决与闸口），以上三条（2)(3)(4) 属**我方约束声明**，能否兑现须在选定服务后复核；核销前原型只显示占位。

### 代记者的可读范围

「授权代记者」此前只写了「可见性独立设置」，未定义可读范围。现约定：

1. 代记的**写入范围**由患者逐项授权（哪一类记录、哪一段时间），授权范围之外的记录**不可写**。
2. 代记者的**可读范围 = 患者就本次授权显式勾选的范围**，默认 **只读该代记者自己写过的条目**；不因授权写入而获得全库可读。
3. **私密标记的记录对代记者一律不可见**，即使在其授权范围内（私密优先于代记授权）。
4. 患者撤回授权后：代记者停止写入与读取；历史条目**保留**并转为患者本人条目，代记标记与授权依据仍可回看。
5. 以上 1–4 为设计约定，**无原型、未实测、未经患者验证**；实现前须在 `UI-DESIGN.md` 授权与隐私设置页落字段，并由 AC11 扩充断言覆盖。
