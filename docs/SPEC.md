# 小贝宝白塞病工作台规格草案

状态：M0 草案，G1 未签；0 患者访谈、0 临床审核。以下场景均为待验证设计假设，不是一手引语。

## 用户与目标

成年患者与其授权代记者，从疑似阶段至长期随访。帮助用户记录发作、整理检查与治疗资料、回顾时间变化、准备跨科复诊。工作台不作诊断、病情分级、治疗选择或因果判断。

## 候选功能与验收

| 功能 | 患者视角假设（非引语） | 可验证结果 |
|---|---|---|
| 发作记录 | 我想记住溃疡何时出现、怎样变化 | 记录日期、部位、用户描述及来源；可修订回看，支持私密标记 |
| 眼部与其他器官资料 | 我想向不同科室说明症状和检查的时间顺序 | 症状与报告可回源；缺项显示未知，不能生成医学判断 |
| 检验与一图秀 | 我想在复诊时看清自己记录的变化 | 同源指标目录、单位方法分组、单点不连线、治疗事件分层，图形不能暗示因果 |
| 治疗记录 | 我想记住使用过的药物和自己的感受 | 保留时间、剂量原文与来源及修订，不提示自行调整 |
| 复诊准备 | 我想带着选好的资料和问题去看医生 | 可选择、预览、回源；私密记录默认排除，导出内容与选择一致 |
| 资料整理 | 我想核对导入资料后再保存 | 云解析显式触发并告知发送原件，抽取仅为候选，用户逐项核对 |
| 原生 Agent | 我想讨论自己选择的内容而不丢失已有输入 | 中间业务区、右侧可调整面板；会话归属、草稿冲突、隐私过滤及不可用状态均须验证 |

## 数据和安全边界

用户明确选择资料目录；不推断、不静默创建。领域事实、来源、记录主体及修订与页面读模型分离。原型数据为合成数据；无患者数据。私密内容在导出、AI、摘要三个出口默认排除；报告解析候选必须经用户确认，不将 AI 输出自动写成事实。所有功能与字段尚待研究和 G1 审核，模型尚未冻结。

## 布局及验证

以业务区为主，原生 Agent 在右侧，参考 [集成合同](../prompts/DSH-AGENT-PANE-INTEGRATION.md)。原型需展示面板宽度、隐藏、窄屏与草稿冲突；宿主模拟不等于 Desktop 实测。原型路径、版本、hash、用户确认范围均待产生；正式业务实现须在相应原型确认之后。指标卡翻面和一图秀按家族标准实测。

## 未决与闸口

患者原话和真实需求、临床资料及适用性、功能优先级、数据合同、宿主版本、MinerU 服务均未核实。G1 需完成需求及 HVT 评审并由用户签认；G2 需交互原型、测试及用户确认；G3 需数据合同确认。测试、装机、业务可用和外部服务各自独立记录。
