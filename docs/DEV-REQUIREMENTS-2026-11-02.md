# 白塞病工作台开发要求（2026-11-02）

## 一、范围与验证

从疑似到长期随访，服务成年患者和授权代记者；先调研和可交互原型，按 G1/G2/G3 签认推进。构建、装机、真实业务、外部服务分别验证。认领见 https://github.com/xyb-openharness-dsh-plugins/.github/issues/56；T1 和波次待维护者 triage。

## 二、样板与产品要求

cervical 仅为客户端接线参考，breast-cancer 为成熟功能比较基准；不复制肿瘤需求或患者叙述。中间业务区与右侧原生 Agent；一图秀与固定高度 3D 卡须按原型完整验证。原型是视觉合同，演示数据单一来源，开发版逐项对照。

## 三、硬约束及来源

患者功能须对应真实患者需求；当前 0 访谈、0 临床审核，任何患者视角表述均为假设。无诊断或处置判断；来源、时间、单位、方法和更正可追溯。私密内容对导出、AI、摘要默认排除。资料目录必须用户明确选择。云解析前告知原件离开本机并由用户触发，候选经核对后才成为事实。测试不能代替真实宿主使用。

基线发现：生成的残留检查器扫描自身词表和测试样本造成误报；排除检查器本身并保留其正反自测，其他脚本中的历史参考单行注明豁免。来源：2026-11-02 `npm run check` 初次输出。接线警告：patch 配置 root 而服务端骨架未声明或使用；当前无存储功能，不视为数据目录已接通，业务实现前必须真实接线并验收。`check-install.mjs` 在继承 DSH_HOME 时错误地指向被规则明确排除的 CLI profile；清除该环境变量重跑后报告未找到 DSH Desktop。不得将 CLI profile 当作 Desktop 安装目标。

## 四、明确未做

真实患者访谈、临床审核、原型、生产数据、MinerU、安装、Desktop 实测与发布均未完成。基线 check 中无原型、临床快照和 primer 的项目被跳过；不能用基线通过证明这些能力。2026-11-02 初次 audit：23/37 通过、12 失败、2 待人工；包括缺面板布局来源、单测与文案检查链、原型及疾病概要等，须在后续阶段逐项补齐并重跑。
