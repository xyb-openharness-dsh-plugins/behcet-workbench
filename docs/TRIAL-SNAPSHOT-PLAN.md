# 白塞病研究登记快照：采集与核验草案

状态：研究准备，未冻结、未实施；本文件不批准生产数据库或临床匹配。具体执行需遵守 `docs/01-WORKFLOW.md` 的九个月优先窗口及扩窗条件，不以探索性结果自行覆盖该规则。

## 采集边界与来源

- 每个来源、查询词和日期窗口分别记录查询参数、执行时间、接口版本、数据时间、HTTP 状态、页数、首屏总数、去重前记录数、错误与终态。失败、拒绝、未查、部分结果和成功零条必须区分；禁止绕过访问控制。
- 首次按九个月窗口检索。探索发现窗口可能漏掉较早登记但仍标注招募中的研究；若窗口覆盖不足，应按工作流记录业务理由再评估最多十二个月的扩窗，不能未经批准把全历史池当正式快照范围。探索全历史可单独标注，不计入正式窗口。
- ClinicalTrials.gov 按登记号去重，不同病种别名分别记查询并保留命中关系。状态与状态核验日期应原样保存；登记状态并不保证当前招募或可入组。其他通道无法查询时明确标记，不以 CTG 代称四通道覆盖。

## 完整性证据

1. 对每条成功查询，保留全部分页、每页响应的哈希与令牌链，记录每页数量及首屏总数；核对去重前条数、唯一登记号数与服务端总数。若服务端数据时间在分页期间发生变化或计数不一致，标记不完整并复查。服务端真实返回零条可以是成功零条；缺乏响应证据的零条不能视为成功。
2. `manifest` 记录来源终态、查询、日期、覆盖范围、源数据时间、分页证据与文件哈希；JSONL 和 SQLite 的记录及来源状态须能复算，记录来源和检索时间。原始资料和生成物的保存范围须事先明确。
3. 原文中缺失的期别、招募状态、中心、入排条件、年龄或性别保持未知；展示原始文本时按文本安全转义，不能由缺失数据生成入组结论。
4. 现有 `scripts/check-trial-snapshot.mjs` 只检查其固定字段、计数、哈希与 SQLite 完整性；不验证所有业务字段、分页完整性或来源状态的真实性。它通过不等于完整检索。后续需另建覆盖检查与正反例，再与现有检查共同运行。
