```bash

# 只跑指定路径
node scripts/path-walk.mjs --only S01,S13
```

## 方法

- 每条路径先 `Page.reload` 隔离，再在看板按文档入口文案精确定位任务卡。
- 入口和所有按钮都用 CDP `Input.dispatchMouseEvent` 真实点击；点击前用
  `elementFromPoint` 校验目标没有被遮挡。不直接调用 `go()`。
- 每次 `render()` 重建 DOM 后重新查询元素，不缓存按钮节点。
- 表单值用原生 value setter + `input`/`change` 写入。无头环境不逐字敲键盘，
  这一点在报告的 `method.formInput` 中明示。
- 判据分六类：入口点击 / 目标页 / 手工步骤 / 产物 / AI 默认通道 / 回首页。
  只有全部 PASS 或文档明确写「—」的 N/A 才算 PASS；NOT_RUN 也算 FAIL。
- 报告记录走查前后的原型 SHA-256，并声明 `method.indexModified: false`。

## 已知局限

- S12 只验证了正常下载提示，没有制造磁盘/浏览器拒绝下载的失败分支。
- S02 示例数据没有冲突来源，冲突并列未验证。
- S03 的「紧急情况联系当地急救服务」在文档中仍是【待核】占位，本次没有把占位当已实现。
- 表单赋值不是逐字键盘输入；真实输入法、焦点顺序、读屏仍需人工/专项走查。
- 本走查不能替代 G2：临床审核、患者访谈、真实宿主与持久化均未验证。

## 维护

路径修复或出现回归时：

1. 更新 `scripts/path-walk.mjs` 的对应断言与入口定位；
2. 运行 `npm run probe:paths`，确认退出码与逐条结论；
3. 更新 `docs/PROTOTYPE-REVIEW.md` 的走查记录和本文结果表。

没有“失败基线台账”。工具契约测试只校验报告是否自洽，不校验“应该失败几条”；
15/15 通过之前，路径门槛保持独立、退出码 1，不能用测试绿灯冒充验收。
