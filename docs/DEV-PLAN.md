## 装机目标（M6）的前置结论

AGENTS.md 规定：**没装 Desktop 就当场停下**，不许用 dev server / `~/.dsh` / CLI profile 顶替，也不许写「已验证」。本机实测：

- `env -u DSH_HOME node scripts/check-install.mjs` → **未找到 DSH Desktop**；
- 上游 `dsh-desktop` **官方不支持 Linux**（无任何 Linux 发行物；打包脚本与 CI 只覆盖 macOS/Windows；源码构建被 `office-runtime` 的 `unsupported native target linux/x64` 硬阻断）。

**因此 M6 在本机不具备执行条件**，届时只能如实记「未验证 / 环境不支持」，**不得**以 Web GUI（http://100.74.124.17:3080）或 CLI profile 冒充 Desktop 装机证据。M7 发布判据中凡依赖 M6 的项同样挂起。

## 下一步及依赖

1. 建立可核查的患者研究记录和场景清单：区分真实叙述、公开资料、设计假设；明确代记授权与撤回、私密内容控制、低精力及失败恢复。不得补造访谈或引语。
2. 获取并核对适用的医学原件、版本、日期和出处，邀请临床审核疾病表述、安全提示及指标口径；未审核内容保持待核，不能生成诊断、处置、分诊、因果或自行调药建议。
3. 将候选场景与页面树及 [交互路径](INTERACTION-DESIGN.md) 双向对齐，补齐孤儿页面和实体；逐项审查 [差异矩阵](DIFF-MATRIX.md)，对实际定稿树复测一级重名率，不把草案计算冒充验收结果。
4. 完成 HVT 五层覆盖和独立评审，解决阻塞项；将版本与未决问题交给真实确认人作 G1 决定。仅有文档或自审不构成签认。
5. G1 后制作原型并获取 G2 确认；G3 后才实现生产数据。实现前确定用户主动选择的资料目录、权限与网络边界；云解析须在发送原件前逐次告知并获得主动授权，候选逐项确认后才进入事实层。

## 实施约束与验证

- 数据事实、原件来源、记录主体、授权与修订可追溯；更正保留版本。私密内容默认不进入导出、AI 上下文和摘要，选择与预览须一致。
- 指标仅在单位、方法和来源可比时展示趋势；单点不连线，未知保持未知。任何分级、阈值或随访节奏先核验适用性与出处；需要参考上限时使用对应报告的上限。
- 原型是视觉和交互合同；开发版用同一事实源和读模型，按冻结原型建立逐项差异及证据。原生 Agent 面板、窄屏、输入保留和失败状态须在目标宿主分别验证。
- 迁移只在数据合同确认后设计和执行，保留旧数据兼容、备份与恢复证据。测试数据标记为合成；不把本地检查、打包或宿主模拟等同真实业务可用。
- 目标为 DSH Desktop；执行 **`env -u DSH_HOME node scripts/check-install.mjs`**（直接跑会因继承 `DSH_HOME` 误判 CLI profile，见 BF-09）并核实实际 profile。**实测未找到 Desktop，且上游不支持 Linux**（见 §装机目标），CLI profile 不是替代目标。发布及外部服务须分别记录执行结果。
